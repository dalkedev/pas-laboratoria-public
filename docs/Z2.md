# Zadanie 2 — Bootstrap

Implementacja znajduje się pod `/z2/` i korzysta z tej samej tabeli `users` oraz mechanizmu sesji co zadanie 1. Punktem odniesienia jest przekazana instrukcja PDF. Archiwum szablonu prowadzącego nie zostało dostarczone; strukturę plików odtworzono na podstawie kodu i wymagań w PDF.

| Wymaganie instrukcji | Realizacja |
|---|---|
| Bootstrap, navbar i obszar treści | Lokalne pliki Bootstrap, `public/z2/header.php` i strony poleceń |
| Menu pobierane przez `myLoadHeader()` | `public/z2/twoj_js.js` ładuje `header.php` do `#myHeader` |
| Grupy poleceń 1.x, 2.x i 3.x, w tym dodane 3.3 | Siedem stron poleceń: 1.1, 1.2, 2.1, 2.2, 3.1, 3.2 i 3.3; osobne pliki `polecenieX_Y.php`, pozycje zdefiniowane w navbarze |
| Własny wygląd | `public/z2/twoj_css.css`; oszczędne zmiany wyglądu i odstępów |
| Rejestracja i logowanie | Formularze Bootstrap; wspólne funkcje uwierzytelniania i bezpieczne sesje z zadania 1 |
| Opcjonalny avatar i domyślna ikona | PNG/JPEG do 2 MiB i 2000 × 2000 pikseli; po walidacji obraz jest zmniejszany do maksymalnie 256 × 256 i ponownie kodowany do PNG, a przy braku pliku używana jest lokalna ikona SVG |
| Przechowywanie avataru | Osobna tabela `user_avatars`, powiązana z `users`; dane obrazu pozostają poza katalogiem publicznych plików |
| Wylogowanie w navbarze | Formularz POST z tokenem CSRF, usunięcie sesji i przekierowanie do logowania |
| Ochrona wszystkich stron poleceń | Wspólny helper w `app/z2.php`; bez sesji następuje przekierowanie do formularza logowania zadania 2 |
| Footer z szablonu | Plik `footer.php` pozostaje częścią struktury, ale nie generuje stopki, zgodnie z późniejszym poleceniem użytkownika |

Rejestracja konta i zapis opcjonalnego avataru odbywają się w jednej transakcji. Endpoint `avatar.php` udostępnia obraz wyłącznie zalogowanego użytkownika. Oryginalna nazwa pliku, jego metadane i przesłana treść nie stają się plikiem wykonywalnym na serwerze. Zapytania SQL używają parametrów, hasła są przechowywane jako hashe, a formularze zmieniające stan wymagają tokenu CSRF.

## Baza i uruchomienie

Świeża instalacja korzysta z `database/schema.sql`. Istniejąca baza zadania 1 wymaga dodania tabeli `user_avatars` przez migrację `database/z2.sql`; ponowne uruchomienie inicjalizacji kontenera z istniejącym woluminem nie wykonuje automatycznie nowych poleceń SQL. Definicja tabeli jest zgodna ze składnią MySQL 5.7: InnoDB, klucz `SMALLINT UNSIGNED` zgodny z `users.id` oraz `MEDIUMBLOB` na dane PNG.

PHP wymaga rozszerzeń `pdo_mysql` i `gd`. Biblioteki CSS i JavaScript oraz domyślna ikona znajdują się lokalnie; przeglądarka nie musi pobierać ich z CDN. Sekrety konfiguracji nadal należą do prywatnego `app/config.local.php`, wyłączonego z GitHuba i paczki wdrożeniowej.

```bash
docker compose up -d --build --wait
python3 tests/z2_smoke.py --base-url http://127.0.0.1:8081
```

## Zakres weryfikacji

Testy HTTP w `tests/z2_smoke.py` sprawdzają działanie funkcji i granice dostępu z użyciem niezależnych sesji. Dostosowanie menu do szerokości ekranu wymaga także kontroli w przeglądarce: zwinięcia, rozwinięcia przyciskiem i ponownej zmiany szerokości. Wyniki faktycznie wykonanych sprawdzeń należy odczytywać z `docs/VERIFICATION.md`; sama obecność testów ani treść tej tabeli nie potwierdzają ich uruchomienia.

Nie przeprowadzono testu na fizycznym telefonie z autoobracaniem ani w kilku przeglądarkach telefonu. Kontrola małego viewportu przeglądarki komputerowej nie zastępuje tych punktów instrukcji. W tej części prac nie wykonano publikacji zadania 2 na hostingu; lokalne uruchomienie i przygotowanie paczki nie stanowią potwierdzenia wdrożenia. Gotowość do zgłoszenia prowadzącemu zależy także od tych sprawdzeń i udostępnienia aplikacji pod adresem wymaganym na zajęciach.
